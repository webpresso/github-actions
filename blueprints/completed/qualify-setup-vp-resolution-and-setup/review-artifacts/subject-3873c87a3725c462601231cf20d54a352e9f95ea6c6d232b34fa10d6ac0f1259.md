# Qualify caller setup resolution

## Product wedge anchor

- **Stage outcome:** The public reusable-workflow stage delivers deterministic, tokenless tool installation for Webpresso consumer CI.
- **Consuming surface:** .github/workflows/self-test.yml exercises .github/actions/setup-webpresso-toolchain/action.yml and .github/actions/setup-wp/action.yml on GitHub-hosted runners.
- **New user-visible capability:** Consumer workflows can rely on qualified Vite+ manifest/catalog resolution and a setup-wp cache miss that demonstrably becomes a cache hit without credentials.

## Summary

Add narrow GitHub-runner qualifications for the consumer-facing setup-webpresso-toolchain composite's manifest-range/catalog resolution and setup-wp's partial-seed-to-isolated-hit cache behavior. Keep PR #54's staged rollout only as provenance; do not change public release routing or credentials.

#### Task 99.1: Qualify consumer composite manifest-range and catalog resolution on a runner

**Status:** __wp-task-status__
**Wave:** 1
**Lane:** qa
**Depends:** None
**Produces:** runner-setup-vp-resolution-receipt
**Consumes:** public-tokenless-setup-wp-contract, pinned-setup-vp-action

Add a GitHub-hosted matrix qualification to self-test.yml that executes the public consumer-facing local setup-webpresso-toolchain composite, not setup-vp directly. Each isolated runner checkout writes a root package.json with caller pnpm metadata and one of: a vite-plus semver range plus matching pnpm-lock.yaml; a vite-plus catalog:vp reference plus named catalog and matching lockfile; or a vite-plus catalog:missing reference whose matching catalog is absent. The composite must use its default root working directory. Give the unresolved case continue-on-error only around the composite action, then assert it failed; valid cases must run vp and match the lockfile-pinned version. Extend parsed YAML tests to bind this runner contract to the local composite's immutable remote invocation and no duplicate install.

**Acceptance:**
- [_] The runner qualification invokes the local ./.github/actions/setup-webpresso-toolchain composite, whose embedded voidzero-dev/setup-vp remote reference remains immutable SHA 49c3e4e92c52e7f8392712a9267bbe71c5ab30e5, with run-install: false and no version or working-directory override.
- [_] A matrix creates root-level caller fixtures for manifest-range, named-workspace-catalog, and unresolved-named-catalog cases. Valid fixtures bind vite-plus through pnpm-lock.yaml to the expected exact version; the unresolved catalog case must make the composite action fail.
- [_] The assertion step checks valid cases report the lockfile-pinned Vite+ version and the unresolved case reports failure, preventing a silent latest fallback.
- [_] A colocated parsed-YAML contract test asserts all fixtures, local composite use, root default working directory, the embedded immutable setup-vp pin, run-install false, absent version override, and the success/failure controls.
- [_] bun test and actionlint pass.

#### Task 99.2: Qualify setup-wp partial-seed-to-isolated-hit behavior on a runner

**Status:** __wp-task-status__
**Wave:** 2
**Lane:** qa
**Depends:** Task 99.1
**Produces:** runner-setup-wp-cache-receipt
**Consumes:** runner-setup-vp-resolution-receipt, public-tokenless-setup-wp-contract

Add a separate runner qualification for setup-wp cache lifecycle. Override RUNNER_TOOL_CACHE to runner temp and precreate a non-executable exact-version cache entry, proving the first public pass safely reseeds partial state. Capture pristine PATH before the first local composite action, require the executable cache path after it, then invoke setup-wp a second time with PATH reset and a nonexistent release-repo. Assert the second action re-exported the cache path through both WP_INSTALL_DIR and command resolution. Extend parsed contract tests around the ordered behavioral controls.

**Acceptance:**
- [_] The cache job sets RUNNER_TOOL_CACHE to a writable runner-temp path and creates a non-executable partial cache file at the exact version-and-architecture target before its first local setup-wp invocation.
- [_] The first pass fetches from the current public release contract and replaces the partial entry with an executable exact cache path.
- [_] Before the second invocation, the job restores a captured pristine PATH so the first pass's GITHUB_PATH export cannot make a no-op second pass appear successful.
- [_] The second local setup-wp invocation uses the same version and a deliberately nonexistent release-repo; afterwards WP_INSTALL_DIR and command -v wp must both equal the seeded cache executable.
- [_] A colocated parsed-YAML contract test asserts the partial-entry setup, ordered first/isolated-second passes, pristine-PATH control, exact cache-path assertions, invalid-network control, and local action paths.
- [_] bun test and actionlint pass.
