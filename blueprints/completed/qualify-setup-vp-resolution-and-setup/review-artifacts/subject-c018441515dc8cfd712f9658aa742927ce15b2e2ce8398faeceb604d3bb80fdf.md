# Qualify caller setup resolution

## Product wedge anchor

- **Stage outcome:** The public reusable-workflow stage delivers deterministic, tokenless tool installation for Webpresso consumer CI.
- **Consuming surface:** .github/workflows/self-test.yml exercises .github/actions/setup-webpresso-toolchain/action.yml and .github/actions/setup-wp/action.yml on GitHub-hosted runners.
- **New user-visible capability:** Consumer workflows can rely on qualified Vite+ manifest/catalog resolution and a setup-wp cache miss that demonstrably becomes a cache hit without credentials.

## Summary

Qualify the consumer setup composite's successful manifest-range/named-catalog resolution and setup-wp partial-seed-to-fresh-runner-hit cache behavior, without changing public release routing or credentials.

#### Task 99.1: Qualify consumer composite manifest-range and named-catalog resolution on a runner

**Status:** __wp-task-status__
**Wave:** 1
**Lane:** qa
**Depends:** None
**Produces:** runner-setup-vp-resolution-receipt
**Consumes:** public-tokenless-setup-wp-contract, pinned-setup-vp-action

Run a hosted matrix through local setup-webpresso-toolchain. Each checkout writes caller pnpm metadata and either vite-plus ^0.1.0/lockfile 0.1.0 or vite-plus catalog:vp/named workspace catalog/lockfile 0.1.1. Set package-manager-cache false because this no-install qualification has no pnpm store to save. Assert exact vp version. Do not assert a missing catalog fails: upstream documents latest fallback with no pinned resolvable version.

**Acceptance:**
- [_] The runner qualification invokes local setup-webpresso-toolchain; its embedded setup-vp remains SHA 49c3e4e92c52e7f8392712a9267bbe71c5ab30e5 with run-install false, package-manager-cache false, and no version or working-directory override.
- [_] A matrix writes root fixture package manifests: ^0.1.0 resolves to lockfile 0.1.0, and catalog:vp resolves through named workspace catalog and lockfile to 0.1.1.
- [_] Each case runs vp and matches its exact lockfile value.
- [_] A parsed-YAML contract test asserts fixture cases, composite use, root default directory, pin, inputs, and exact versions.
- [_] bun test and actionlint pass.

#### Task 99.2: Qualify setup-wp partial-seed-to-fresh-hit behavior on hosted runners

**Status:** __wp-task-status__
**Wave:** 2
**Lane:** qa
**Depends:** Task 99.1
**Produces:** runner-setup-wp-cache-receipt
**Consumes:** runner-setup-vp-resolution-receipt, public-tokenless-setup-wp-contract

Add dependent hosted seed/hit jobs. The seed safely reseeds a partial exact cache entry, executes it, and tars only its subtree. The fresh hit restores the artifact, calls local setup-wp with invalid repository, and proves the action republishes and runs the restored binary.

**Acceptance:**
- [_] A writable RUNNER_TOOL_CACHE seed job creates non-executable wp/0.0.6/x64/wp, invokes local setup-wp against public release, requires the path executable, and runs it with --help.
- [_] The seed archives only the cache subtree and uploads it with actions/upload-artifact@ea165f8d65b6e75b540449e92b4886f43607fa02.
- [_] A fresh hit job downloads through actions/download-artifact@d3f86a106a0bac45b974a628896c90dbdf5c8093, restores under its own RUNNER_TOOL_CACHE, and invokes local setup-wp at 0.0.6 with a nonexistent release-repo.
- [_] The hit asserts WP_INSTALL_DIR and command -v wp equal its restored cache executable, then runs it with --help.
- [_] A parsed-YAML contract test asserts partial seed, artifact transfer, dependency, remote SHAs, invalid-network control, exact paths, and execution.
- [_] bun test and actionlint pass.
